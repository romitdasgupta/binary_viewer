Privacy

What happens to a file you open, what is logged, and what your browser keeps. Last updated [DATE].

This site is run by [OPERATOR NAME]. Questions about this page: [CONTACT EMAIL].

In short. BinaryStudio reads files; it never runs them. The status bar of the tool says which of three modes you are using. In browser: your file never leaves your device. Hosted: your file is sent to this server, kept in memory while you use it, then dropped. It is never written to disk and never logged. Local: the server runs on your own machine. BinaryStudio sets no cookies.

What happens to a file you open

In browser (the static site)

The analysis engine is downloaded from this site and runs inside your browser tab, in a Web Worker. Your file is read by your browser and analysed there. It is not uploaded, not even in part, and this site has no server that could receive it. The status bar shows In browser.

A service worker keeps a copy of the site's own files (the page, scripts and the engine) so the tool works offline. It never stores the files you open.

Hosted (a BinaryStudio server)

Your file is uploaded to this server over the connection you are using. The status bar shows Hosted. Then:

  • The file and the analysis results are held in the server's memory. They are not written to disk.
  • The file is addressed by a random identifier of 128 bits. That identifier is the only way to reach it, and the tool never puts it into a link or the address bar. Anyone who has the identifier can read the file until it is dropped, so do not share it.
  • The file is dropped after it has gone unused for 30 minutes. It can be dropped earlier when the server needs the memory for other people's files, and all files are gone when the server restarts. The operator can change the 30 minutes; this server uses [30 MINUTES, OR THE VALUE OF BINARYSTUDIO_DOC_TTL].
  • Patched copies you make in the Labs are treated the same way.
  • The file is analysed, never executed.

Local

When you run python3 binary_viewer.py yourself, the server runs on your own machine and files stay on it. The status bar shows Local.

What the server logs (hosted mode)

For each request the server writes one line to its log. The line holds the time, your IP address (for IPv6, only the first 64 bits), the method, the path without its query string, the response status, the time taken, the number of bytes sent each way, and the kind of document asked for ("an upload", never its identifier).

The log never contains the contents of your file, its name, or the analysis results. When something fails, the log records where in the code the failure happened, but not the error text, because that text can quote bytes of the file.

The IP address is used to limit how many requests one client can make. Logs are kept for [LOG RETENTION PERIOD] by [HOSTING PROVIDER / WHO STORES LOGS].

The reverse proxy or CDN in front of this server may keep its own logs: [PROXY OR CDN, AND WHAT IT LOGS]. The proxy configurations shipped with BinaryStudio remove upload identifiers and file names from those logs.

What your browser stores

BinaryStudio sets no cookies. It keeps a few settings in your browser's local storage, under keys that start with binarystudio:. They never leave your device:

  • layout, theme, and the state of the tree and hex views;
  • the last sample (or, in local mode, the last file path) and view, so the tool can reopen where you were. Uploaded files are never recorded;
  • your progress through the Learn articles and tours;
  • what you typed into the Labs (for example, bytes in the encoding lab, or the settings of the ELF builder);
  • if this site asks before showing ads, your answer.

To clear all of these, clear this site's data in your browser's settings.

Learning pages

The pages under Learn are plain documents. They load nothing from other sites, except an ad if ads are enabled (see below).

Advertising

BinaryStudio can show ads, but it does not unless the operator turns them on. On this site ads are [OFF / ON: NAME THE PROVIDER].

The rules are the same whichever provider is used:

  • Code from an advertiser or ad network never runs inside this site. An ad is either drawn by BinaryStudio's own code as plain text, an image and a link, or shown in an isolated frame. That frame cannot read this page, your files or your settings.
  • Ads appear on the learning pages, beside or below the text. They appear in the tool itself only if the operator turns on a separate strip under the status bar. They are never placed between you and the data you are analysing.
  • Every ad is labelled. Ad links are marked as sponsored.
  • If your browser sends Do Not Track or Global Privacy Control, no ad network is contacted at all.

What each provider means for you:

  • Sponsor units written by the operator. Your browser makes no request to anyone else, except to load an image the operator hosts elsewhere, if any.
  • EthicalAds. Your browser asks EthicalAds' server for one ad and loads its image. EthicalAds receives your IP address, your browser's user agent, and the address of the page without its fragment. It never receives anything about your files. EthicalAds describes what it does with this data in its privacy policy, at ethicalads.io/privacy-policy.
  • A framed ad from another network. The network's page runs in the isolated frame and may set cookies of its own. This site asks you first and loads nothing until you answer. Its privacy policy: [NETWORK AND LINK TO ITS POLICY].
